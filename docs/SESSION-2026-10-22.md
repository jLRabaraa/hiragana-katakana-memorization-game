## What Phase 3 delivered

### Engine layer (`src/engine/`, no React imports)

- `types.ts` — the question model as a discriminated union on `kind` (`choice`, `typing`, `match`,
  `particle`, `assembly`), where `choice` uses a flattened `ChoiceVariant` (`direction` +
  `answerLabel`) and `MatchPair` carries `itemId/tile/slot/long`.
- `progress.ts` — the `kanaDojo.progress.v2` store: per-level `passed/learnedAt/bestAccuracy/
  bestScore`, per-item miss tallies, and practice config. Field-by-field validation on read,
  silent legacy migration from `kanaDojo.config.v1` / `kanaDojo.best.v1`, and `markLessonSeen` /
  `completeRound` folds. `passed` is permanent once reached (bests only ever go up).
- `gating.ts` — `levelStatus`, `learnedItemIds`, `nextPlayableLevel`; `buildRound` refuses locked
  levels and levels whose lesson has not been completed.
- `spiral.ts` — ~25% review share, weighted `1 + wrong` (capped), drawn only from the learned pool.
- `questionBuilder.ts` — the single round factory `buildRound(levelId, progress)`. Kana rounds ship
  6 choice + 2 typing + 2 match questions; vocab rounds keep the same shape with the same
  direction logic; grammar rounds build 6 particle + 2 assembly questions from curated data.
  Distractors are deduplicated by visible label *and* normalised reading.

### Screens and engines (`src/features/`, `src/app/`)

- `home/HomeScreen.tsx` — level map with locked stubs, per-level status, progress bar, sound
  toggle, and the dev-only curriculum-review link.
- `learn/LessonScreen.tsx` — lesson cards for `level.learn` plus notes; shown once per level.
- `quiz/QuizScreen.tsx` — round controller: HUD (progress, streak pill, score), one document-level
  key handler (`1`–`4`, `Enter`, ignoring INPUT/TEXTAREA), per-question key registration, tallies,
  feedback with on-miss mnemonics, and a `RoundSummary` handed to the results screen.
- `quiz/questions/` — five engines: `ChoiceQuestion`, `TypingQuestion` (Hepburn/Kunrei via
  `kanaRomajiVariants`), `MatchQuestion`, `ParticleQuestion`, `AssemblyQuestion`.
- `quiz/useTileDrag.ts` — Pointer-Events drag (6px slop, cloned ghost, `touch-action: none`) plus
  the tap-tile-then-tap-slot fallback with the `suppressClicksUntil` guard; shared by matching and
  word-order assembly.
- `results/ResultsScreen.tsx` — accuracy gauge, stats, per-item review list with mnemonics, retry /
  next / map actions, confetti (skipped under `prefers-reduced-motion`).
- `app/App.tsx` — small state machine: `home → lesson → quiz → results` (+ dev review). Retries
  remount the quiz with a fresh round; a passed level never re-locks.
- Design system additions appended to `src/styles/global.css` (map rows, lesson cards, grammar and
  assembly styles, mobile media block) reusing the legacy tokens.

### Utilities

- `src/utils/kanaToRomaji.ts` — kana → romaji parsing for typing acceptance (sokuon, ん variants,
  Kunrei substitutions, ō/uu spellings).
- `src/utils/audio.ts` — WebAudio tones + `speechSynthesis` (ja-JP), every path failing silently.

## Bug found and fixed during verification

Spiral-review kana items inside a *vocab* level (e.g. ぎゅ reviewing from an earlier hiragana
level) built choice questions with **zero distractors** — the level's pool has no kana items, so
the kana candidate pool was empty. `resolvePool` now falls back to the global kana/vocab lists for
distractor selection whenever the level pool lacks a type. The probe stress loop initially caught
this only intermittently (shuffle-dependent) — worth remembering when doing content changes.

## Manual browser pass (pending for the reviewer)

The dev server (`npm run dev`) exposes everything; suggested checklist at mobile width (< 470 px):

1. First level: lesson → quiz. Try choice by mouse *and* keys `1`–`4`; typing with Enter; drag
   **and** tile-then-zone taps on matching; particle chips; assembly taps.
2. Fail a round on purpose → results shows review list; retry skips the lesson.
3. Pass → next level unlocks; verify a passed level stays passed (settings reset to test).
4. Sound toggle persists across reloads; arithmetic of score/streak visible in the HUD.
