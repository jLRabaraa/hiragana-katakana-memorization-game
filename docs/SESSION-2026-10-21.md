# Session Summary — 2026-10-21

Handoff document for the design interview and the first two build phases of Kana Dōjō.

## Where this started

The repository held a finished, single-file browser game (`index.html`, ~2,550 lines): a kana quiz
with hiragana/katakana, basic/voiced/combination sets, five practice modes (mixed, matching, reading,
recall, typing), scoring, streaks, a timer, speech synthesis, and `localStorage`. It worked, but it
only *drilled* — it never taught, had no progression, and knew nothing beyond kana.

The goal set for this session: grow it into a game that takes a **complete beginner** through
hiragana, katakana, and the most common kanji, with a **leveling system** that eventually unlocks
sentence-structure practice. The existing game was the proof of concept.

## What the design interview decided

The whole interview is recorded with alternatives and rationale in
[`DECISIONS.md`](DECISIONS.md). The short version:

- **Learn before drill** — each level opens with lesson cards, then quizzes them.
- **Kanji through vocabulary** — 水 is taught as みず (water), never as an isolated symbol/reading.
- **Full kana first** — hiragana, then katakana, basic → voiced → combinations, before kanji.
- **Accuracy gate at 80%** — passing unlocks the next level; retries are immediate and lenient, and
  a passed level never re-locks.
- **Spiral review** — ~25% of questions come from previously missed items, weighted by miss count,
  enforced by the engine.
- **On-miss mnemonics only** — shown in wrong-answer feedback, not on every lesson card.
- **Stack: React + TypeScript + Vite** — chosen partly for employability, partly because the screen
  count and data models outgrew a single HTML file.
- **Vercel host** (GitHub Pages documented as an alternative), `localStorage` progress, no backend.
- **Curated curriculum + dataset enrichment** — hand-picked words and sentences; JMdict,
  KANJIDIC2, and Tatoeba only fill in readings, metadata, and examples.
- **Engine-enforced locks** — locked levels render as stubs and the question builder refuses to draw
  from unlearned stages.

  `docs/DEPLOYMENT.md`, `docs/DECISIONS.md`, `THIRD_PARTY_LICENSES.md`, rewritten `AGENTS.md`.
- Verified: typecheck, lint, production build.

### Phase 2 — curriculum

- Domain types in `src/types/domain.ts` (kana/vocab items, grammar questions, levels, kanji info).
- **Kana**: all 46 basic + 25 voiced + 33 combination, both scripts = 208 items
  (`src/data/curated/kana.ts`), with Kunrei alternates and mnemonics for the 92 basic glyphs.
- **Vocabulary**: 14 words across two levels, teaching 14 kanji inside words
  (`src/data/curated/vocab.ts`), with glosses, examples, and miss mnemonics.
- **Grammar**: 12 questions — 8 particle fill-ins (は/を/に/で/も) and 4 word-order assembly
  questions — plus explanation notes (`src/data/curated/grammar.ts`).
- **Campaign**: 16 ordered levels with auto-chained `requires`, 80% pass thresholds
  (`src/data/curated/levels.ts`).
- **Enrichment pipeline**: `scripts/convert-datasets.ts` + `npm run data:convert`; validates
  curated data, optionally reads `data/raw/` JMdict/KANJIDIC2/Tatoeba, writes
  `src/data/generated/*.generated.ts`. Runs in curated-fallback mode until datasets are downloaded.
- **Data layer**: `src/data/index.ts` — id maps, item lookup, structural validation run in dev.
- **Review screen**: `src/features/review/CurriculumReview.tsx`, linked from the home screen in dev
  only. Tabs: Levels (16), Kana (208), Words (14), Grammar (12).
- Verified: typecheck, lint, production build (77 KB gzipped).

## Checkpoint 1 — pending review

Items to verify in the review screen before Phase 3:

1. **Kana readings/alternates** — especially ぢ/づ, を (`wo`, accepts `o`), ん (`n`, accepts `nn`),
   and the two-level yōon split.
2. **Word glosses/readings** — 日 vs 火 (both `ひ`), verb okurigana (飲む/食べる/見る/行く).
3. **Mnemonics** — whether the anchors are useful; katakana entries are intentionally simple.
4. **Sentences** — particle accuracy and naturalness. Known flags: 家で月を見ます is grammatical but
   semantically odd; several example sentences (日がのぼります, 月がきれいです, 家に帰ります) use
   structures not yet taught and are illustrations only, not drill material.
5. **Kanji choice** — confirm the first 14 kanji are the desired set for the slice.

## Next steps

### Phase 3 — engines

1. Progress store (`kanaDojo.progress.v2`): level results, item miss weights, best scores; validate
   on read; migrate from legacy `kanaDojo.config.v1` / `kanaDojo.best.v1`.
2. Question builder: gating, 75/25 new/spiral mix, round lengths (10 choice/typing, 6 drag, 8
   grammar), distractor dedupe by label and reading.
3. Lesson phase: cards for `level.learn`, shown once per level.
4. Quiz engines: port choice, typing, drag; add particle-fill and assembly (reuse drag).
5. Checkpoint 2: grammar sentence review before locking grammar into the flow.

### Phase 4 — vertical slice

- Level map with locked stubs; end-to-end flow (map → lesson → quiz → results → retry).
- On-miss mnemonic feedback, free-practice Dojo using the legacy settings, mobile/pointer polish.
- Final deployment to Vercel; verify the smoke-test checklist in `docs/DEPLOYMENT.md`.
