# AGENTS.md

Kana Dōjō is a level-based Japanese learning game: React + TypeScript + Vite, static build, no
backend. A complete beginner starts with hiragana and progresses through katakana, vocabulary
(kanji taught inside words), and first sentence structure. Progress is stored in `localStorage`.

**Current phase: 2 — curriculum authored (Checkpoint 1 awaiting review).** The campaign data lives
in `src/data/curated/` (hand-authored) and `src/data/generated/` (enrichment output). In development,
the home screen links to a read-only curriculum-review page; it is excluded from production builds.
Engines and campaign screens are built in Phases 3–4. The original single-file game is preserved at
`legacy/kana-dojo-legacy.html` as a working reference.

## Commands

```bash
npm install
npm run dev        # Vite dev server, http://localhost:5173
npm run build      # tsc -b && vite build -> dist/
npm run typecheck  # tsc -b
npm run lint       # oxlint
npm run preview    # serve dist/
```

Run `npm run typecheck`, `npm run lint`, and `npm run build` before calling work done. There is no
test framework yet; do not add one without being asked.

## Layout

```
src/app/         App shell + screen switching
src/components/  Shared UI (AttributionFooter, buttons, cards…)
src/data/        curated/ (hand-authored) and generated/ (converted datasets)
src/engine/      Pure logic: question builder, spiral weights, gating (no React imports)
src/features/    home/ (level map), learn/, quiz/, results/
src/hooks/       Persistence and shared hooks
src/styles/      global.css — the entire design system, ported from the legacy game
src/types/       Domain types (KanaItem, VocabItem, Level, Progress, Question)
src/utils/       normalizeRomaji, shuffle, escapeHTML, audio helpers
scripts/         Dataset conversion (Phase 2)
```

Keep engine code free of React so it stays testable and reusable. Do not pre-create empty folders
for later phases.

## Domain rules (non-negotiable)

- **Locked content never renders or builds.** The level map renders stubs only, and
  `buildRound(levelId, progress)` must refuse locked levels and refuse items whose lesson has not
  been completed. Locking is logic, not CSS.
- **Learn before drill.** Every level shows its lesson once (`level.learn` cards), then quizzes.
  Retries skip the lesson. A passed level never re-locks.
- **Kanji only inside vocabulary.** Never create isolated kanji/reading items; a kanji must appear
  in a taught word first. This keeps typing unambiguous.
- **Spiral review is engine-computed.** ~25% of questions come from previously learned items
  weighted by `1 + wrong` (capped), only from the learned pool.
- **Accuracy gate:** pass at `level.passAccuracy` (0.8). Accuracy = correct questions / total.
- **Kana data is hiragana-only in source.** Katakana glyphs are generated by the U+3041–U+3096 +
  0x60 offset (`toKatakana`). Never run that transform across mixed strings (vocab, sentences).
- **Stable ids.** Ids like `hira:あ`, `vocab:みず`, `kana-01` are persisted in `localStorage`; never
  derive them from array positions and never renumber existing levels.

## TypeScript

- `strict` mode via the Vite template; do not weaken tsconfig flags.
- Model questions as discriminated unions on `kind`; exhaustively handle kinds.
- Avoid `any`. DOM queries return `Element | null` — narrow or guard.
- Prefer `type` for data shapes, `interface` for extensible component props.
- All data crossing a module boundary is typed; no untyped JSON imports.

## Persistence

- Key: `kanaDojo.progress.v2` (shape in `docs/ARCHITECTURE.md`).
- Validate the saved object field by field on read; fall back to defaults on anything malformed.
  Never let a corrupted store crash the app.
- Migrate from legacy `kanaDojo.config.v1` / `kanaDojo.best.v1` once, without deleting them.
- Save on round end / level pass — not on every keystroke.
- Bump the key version and ship a migration whenever the shape changes.

## UI and interaction

- One global stylesheet with CSS custom properties in `:root`. Reuse `--paper`, `--ink`, `--red`,
  `--green`, `--gold`, `--radius`, and the `.panel`, `.screen.is-active`, `.quiz-card` patterns
  rather than inventing new visual language.
- Only the active screen is mounted/visible. The quiz card re-renders per question with that
  question's data only.
- **Drag uses Pointer Events, not HTML5 DnD** (`pointerdown/move/up`, cloned ghost element,
  `touch-action: none`) plus a tap-tile-then-tap-slot fallback. Keep the `suppressClicksUntil` guard
  so the click after a drag does not select a tile. This applies to kana matching and grammar
  word-order assembly.
- Keyboard: one document-level handler for `1`–`4` and `Enter`, ignoring INPUT/TEXTAREA. Per-question
  handlers live in the component that renders the question.
- Escape all user-entered text before it reaches feedback (`escapeHTML`). Kana/vocab/sentence data is
  trusted static content.
- Feedback regions use `aria-live="polite"`; icon buttons need labels; focus outlines must stay.
- `prefers-reduced-motion` disables animations and confetti.
- Verify at mobile width (< 470 px); drag/tap must both work.

## Rōmaji

Typing and choice matching go through `normalizeRomaji()`: lowercase, strip macrons and non-ASCII,
compare against `romaji` plus `alts` (Kunrei forms such as `si`, `ti`, `tu`, `hu`, `zi`). Choice
distractors are deduplicated by visible label **and** by normalised reading.

## Audio

WebAudio-synthesised tones for correct/wrong/place/finish; `speechSynthesis` with `lang: 'ja-JP'`
for pronunciation. Every path degrades silently when unavailable or when the sound toggle is off.
Never let audio throw into the UI.

## Content and licensing

- Curated curriculum lives in `data/curated/`; datasets only enrich it (`docs/DATA-PIPELINE.md`).
- Do not commit raw dictionary dumps (`data/raw/` is git-ignored); commit only converted slices.
- JMdict/KANJIDIC2 (CC BY-SA 3.0) and Tatoeba (CC BY 2.0 FR) require visible attribution. Keep the
  `AttributionFooter` rendered and `THIRD_PARTY_LICENSES.md` accurate. Generated data keeps its
  licence header.
- Any change to learning content needs the review checkpoint in `docs/DATA-PIPELINE.md` before it is
  wired into levels.

## Deployment

Vercel is the primary target; `vercel.json` pins the Vite build and SPA fallback. Do not change
`base` to a repo path for Vercel. GitHub Pages needs a `/repo-name/` base — see `docs/DEPLOYMENT.md`.
